## 二、輸出欄位契約

| 欄位名稱 | 型別／限制 | 用途 | 畫面標籤 | 如何查原文 |
|---|---|---|---|---|
| plan_title | String，不可為空 | 顯示本次運動計畫名稱 | 計畫標題 | 查看 JSON 的 plan_title |
| weekly_summary | String，不可為空 | 說明整週運動安排 | 每週計畫摘要 | 查看 JSON 的 weekly_summary |

## 三、測試紀錄

本次測試分成程式檢查及實際操作兩個部分，避免將尚未完成的項目直接當成通過。

| 項目 | 實際輸入／操作 | 預期結果與檢查方式 | 人工判讀與修正 | 證據類型 |
|---|---|---|---|---|
| 空白 | 其他運動偏好不填，使用表單預設選項 | 可以不填寫其他偏好，仍可提交表單 | 其他偏好屬於選填資料，不影響基本功能 | 程式設計檢查 |
| 過長 | 其他運動偏好輸入超過 1000 字 | 輸入欄位限制最多 1000 字，程式也有長度檢查 | 避免使用者輸入過長內容 | 程式設計檢查 |
| 正常資料 | 選擇運動目標、程度、天數、時間及器材，再勾選 API 同意並提交 | 預期產生運動計畫，包含摘要、每日運動項目及一般建議 | 應檢查回傳內容是否符合使用者輸入，以及運動時間是否合理 | 本機操作；真實 API 結果須以實際測試為準 |
| 資訊不足 | 其他偏好留白，只使用表單提供的基本資料 | AI 依照已提供的資料安排運動計畫 | 檢查是否出現不符合輸入條件的內容 | 待進一步測試 |
| 結果保存／再送出失敗 | 先產生一筆計畫，再提交另一筆請求 | 每次提交時先清除舊結果，若新請求失敗則顯示錯誤 | 避免失敗後仍顯示上一筆結果，造成誤認 | 程式設計檢查 |
| 缺少 API Key／服務失敗 | 檢查 API Key 讀取及錯誤處理程式 | 找不到金鑰時顯示錯誤；API 發生例外時顯示錯誤訊息 | 避免程式因為金鑰或連線問題直接中斷 | 程式設計檢查 |
| Cloud 部署 | 使用 Streamlit Community Cloud 部署並測試 | 部署成功後，應能透過網址開啟網頁並產生運動計畫 | 目前尚未完成雲端驗收，完成後補上網址及測試結果 | 尚未完成 |

### 6. 本次反思

這次專題讓我了解如何把 AI API 實際應用在一個可以操作的網頁程式中。原本以為只要輸入問題，AI 就能直接產生結果，但實際製作後才發現，還需要考慮使用者輸入資料、AI 回傳格式、API 金鑰管理及錯誤處理等問題。

我認為這個專題比較有用的地方，是可以依照使用者的運動目標、程度及可運動時間，整理出每天的運動重點和項目，讓不知道如何開始運動的人有一個參考方向。

製作過程中，我也遇到虛擬環境、套件安裝、檔案路徑及程式縮排等問題，透過查找資料和 AI 協助才逐步排除。目前已經完成本機程式的基本啟動，接下來還需要持續確認真實 API 回傳結果，並完成雲端部署及測試。

這個程式目前仍有一些限制，例如 AI 產生的運動計畫不一定完全適合每個人的身體狀況，因此使用者仍需要依照自身情況調整，不能完全取代專業運動指導。

下一步希望完成 Streamlit Community Cloud 部署，讓其他人也能透過網址使用這個工具，並測試不同輸入條件下的結果，讓整個專題更加完整。

目前已知的限制是 AI 產生的運動計畫仍需要人工確認，不能完全取代專業運動指導。下一步希望完成雲端部署，確認 API 可以正常運作，並進一步測試不同使用者需求下產生的運動計畫是否符合預期。
